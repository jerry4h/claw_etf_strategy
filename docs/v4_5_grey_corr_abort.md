# v4.5 灰区相关保护立项评估与中止复盘

> 任务 #29（预研）→ #32（T1 配置）→ #33/37（T2 参数网格）→ #39（M-D 门控）  
> 结论：**结构性不可行，立项中止**。生产维持 v4.3/v4.4 不变。  
> 保留项：grey_corr_combo 对抗评估监控情景。

---

## 1. 缺口实证

### 1.1 问题发现

Layer 3.5（危机相关性加成）的 v4.4 参数（threshold=0.60, slope=1.875）在一类特定压力情景下
存在缺口：**持续中相关 + 高波动（grey zone × σ1.5）**。

| 情景 | DGP 参数 | v4.3 中位 MaxDD | v4.4 中位 MaxDD | 12% 红线 |
|---|---|---|---|---|
| grey_corr_combo | regime_corr, ρ=0.50, p_enter=1.0, p_stay=1.0, σ×1.5 | 12.81% ✗ | 12.81% ✗ | ≤12% |

该情景描述：进攻资产全程维持中等相关（EWMA max|ρ| ≈ 0.50，恰在 0.30-0.60 "灰区"），同时
波动放大 50%。v4.4 阈值 0.60 不会触发保护（相关未达线），策略在持续高波动中无额外防御。

### 1.2 灰区历史实证

对真实历史 650 周数据分析（任务 #29）：
- 灰区（0.30 < EWMA max|ρ| < 0.60）覆盖历史 **39.8%** 时间
- 灰区段内策略 MaxDD 全部 **≤ 3%**（历史上灰区从未叠加极端波动）
- grey_corr_combo 属**理论尾部**——历史未实现，但对抗框架需覆盖

## 2. 候选机制与否决

### 2.1 M-C：纯参数降阈值/缓坡（12 格网格，全 FAIL）

**思路**：降 threshold（0.60 → 0.40-0.50）使灰区也能触发 boost，减缓 slope 避免过度保护。

**参数网格**：threshold ∈ {0.40, 0.45, 0.475, 0.50} × slope ∈ {0.60, 0.75, 0.90} = 12 格

**结果**：

| 阈值 | grey_corr_combo 最佳格 MaxDD | bond_bear 对应格 MaxDD | 判定 |
|---|---|---|---|
| 0.40 | 11.22% ✓ | 12.32% ✗ | FAIL（bond_bear 破线） |
| 0.45 | 11.19% ✓ | 12.32% ✗ | FAIL |
| 0.475 | 11.54% ✓ | 12.32% ✗ | FAIL |
| 0.50 | 11.88% ✓ | 12.32% ✗ | FAIL（grey 也边际） |

**根因**：bond_bear DGP（`mudef_mult=0.5`）下进攻对 EWMA 相关中位 ≈ **0.40**，恰落灰区：

| 阈值 | bond_bear 中 boost 触发率 | v4.4 触发率 |
|---|---|---|
| 0.40 | 46.8% | — |
| 0.45 | 37.1% | — |
| 0.50 | 27.1% | — |
| 0.60（v4.4） | 10.5% | 10.5% |

降阈值必然在 bond_bear 中大量触发 boost → 把权重推向正在"半下跌"的防御资产 → MaxDD 恶化。

### 2.2 M-D：条件门控（24 格网格，全 FAIL）

**思路**：在 boost 触发前加门控——仅当防御资产健康时放行 boost，防御下行时关闭。

**4 种门控信号**：

| 门控 | 信号 | 基线关闭率 | 约束(<5%) |
|---|---|---|---|
| A | defense NAV / SMA-13 > 0.98 | 8.3% | ✗ |
| B | defense 26 周累计收益 > 0 | 19.7% | ✗ |
| C | defense 26 周最大回撤 < 5% | 31.1% | ✗ |
| D | defense 近 4 周收益 > -2% | 11.1% | ✗ |

**参数网格**：thr ∈ {0.45, 0.475, 0.50} × slope ∈ {0.60, 0.75} × gate ∈ {A,B,C,D} = 24 格

**三层失败机理**：

1. **Gates A/C/D 无法检测 bond_bear**：bond_bear DGP 防御漂移仍为正（年化 ~2.5%），
   SMA/回撤/短期收益信号在正趋势下不触发关闭 → bond_bear MaxDD 不变（12.32%）

2. **Gate B 检测成功但 FPR 超标**：26 周累计收益 < 0 在历史 650 周中有 128 周触发（19.7%），
   远超 5% 约束。即便放宽该约束，快筛通过的 5 格在全量评估中仍因 grey_corr_combo
   Sharpe 劣化 > −0.02 和 offense_cooldown MaxDD +2.0pp 而全部失败

3. **结构性两难**：bond_bear 是低信噪比情景——漂移仍正、波动正常——统计上与正常态不可
   区分，任何简单统计信号都无法在可接受误报率下将其与正常环境分离

## 3. 结构性根因

核心矛盾可精确表述为：

```
灰区保护需求：threshold ≤ 0.50（使 grey_corr_combo 中 ρ≈0.50 能触发）
bond_bear 零劣化：threshold > 0.55（使 bond_bear 自然 ρ≈0.40 不触发）
```

两个约束**物理冲突**——在单阈值标量机制下无解。

门控试图通过条件分支绕开冲突，但 bond_bear DGP 的设计特征（防御仅半衰、统计分布与
正常态高度重叠）使得任何基于防御端统计量的门控都面临"检测力 vs 误报率"的本质权衡——
检测阈值松则 FPR 超标影响 realized，检测阈值严则漏检 bond_bear。

**结论**：纯标量阈值/斜率 + 简单健康门控，36 格实验穷尽可行空间，证实**不可行**。

## 5. v4.6+ 方向（远期可选课题）

**定向 boost**（仅施加至进攻端而非全投组）：
- 当前 boost 机制：检测到高相关 → 整体增加防御比例 → 对全投组施加统一效果
- 改进方向：检测到高相关 → 仅对进攻端降权（不增加防御绝对水平）→ 避免在防御下行时
  反而增加防御暴露的副作用
- 工程量估计：改 `src/engine_core.py` 的 `_compute_crisis_boost_ewma()` + 新增配置字段，
  约 50-100 行
- 前置依赖：需重新设计 boost 应用点（当前 boost 在回测循环中直接加到 def_alloc 上），
  属架构性改动

**本版不做**。作为 v4.6+ 可选课题存档。
