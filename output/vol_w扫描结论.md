# vol_w 黄金偏好扫描结论（P0 验证）

> **【结论状态】已证伪（P0 不成立）。** 降 `vol_w` 去黄金偏好不能改善跑输等权等权基准，反而恶化 Sharpe/WF；低波/黄金倾斜是策略 edge 来源。本扫描为一次性验证，无遗留待办项。


> 日期：2026-07-26 ｜ 基于 `claw_etf_strategy` v3.1（扫描在 value-guard 补丁默认关闭态=基线完成；该补丁已于本轮提交移除，结论不受影响）
> 目的：验证优化建议文档 P0 项——"降 `vol_w` 削减黄金偏好可改善跑输等权（WF 55.6%）"。

## 0. TL;DR（重要，先说结论）

- **P0 原假设被数据证伪**：降 `vol_w`（削减黄金偏好）**不能**改善跑输等权，反而使 Sharpe 与 WF 双双恶化。
- `vol_w=1.10`（基线）本身就是 Sharpe / 年化 / MaxDD 的**近最优点**，当前配置已被良好选择。
- 4 个失败窗口（W0/W2/W5/W7）对 `vol_w` 变化**高度鲁棒**——降 `vol_w` 一个都修不了，反而让 W0/W5 的差距拉大。
- **结论反转**：低波/黄金偏好是策略的 **edge 来源，不是 bug**。优化建议文档里"去黄金偏好"这条 P0 应撤回。

## 1. 方法

- 扫描 `vol_w ∈ [0.0, 0.4, 0.7, 0.9, 1.10, 1.40]`，每个值：
  - 全样本回测 → Sharpe / 年化 / MaxDD / Calmar / 黄金平均权重 / 防御周
  - 9 窗口 WF 相对胜率（`compute_benchmark_relative_win_rate`，OOS 纪律）
  - 逐窗口 strat_sharpe vs bench_sharpe（重点看 4 个失败窗口 gap）
- `mom_w=1.0` 固定，其余同基线 v3.1（value-guard 参数已于本轮提交移除，扫描当时即为其默认关闭态=基线，结论不变）。

## 2. 过程透明：第一次扫描的 bug（我自己犯的，已修）

- 初版扫描把 `vol_w` 写进 YAML 的 **`selection`** 段，但真实字段在 **`scoring`** 段（`vol_w=scoring.get('vol_w')`）。覆盖失效 → 结果逐位不变（误报"vol_w 无效"）。
- 修正为 `scoring.vol_w` 后结果正常。这印证了 `vol_w` 在 `backtest.py` line 282 确实被消费，**策略无 bug，是我脚本的配置键名陷阱**。
- 顺带验证了仓库里 `vol_w` 是唯一生效的低波权重（无重复/死字段干扰）。

规律：
- **W0/W2/W5 在所有 vol_w 下必然跑输**，降 vol_w 不仅不修复，W0 差距从 -0.81 恶化到 -1.47。
- 仅 W7（最近 2024-25）在 `vol_w=1.40`（进一步加黄金偏好）时边际翻正 +0.012，但代价是整体 Sharpe 从 1.610 掉到 1.567。
- 没有任何 `vol_w` 值能"既提 Sharpe 又提 WF"——不存在免费午餐。

## 5. 解读

### 5.1 黄金偏好是 edge，不是 bug
- 黄金平均权重随 `vol_w` 单调变化（1.10→28.27%；0.0→18.67%），证明机制连通、参数生效。
- 但**降低** `vol_w` → Sharpe 1.610→1.076、WF 55.6%→44.4%：低波倾斜（含黄金）贡献了收益**与**稳健性。
- 所谓"过度加权低波黄金"在回测里表现为**正贡献**，并非拖累。

### 5.2 4 个失败窗口的根因不在低波倾斜
- 即便把黄金几乎移出 TOP2（vol_w=0.0，GoldW 18.67%），4 个窗口仍全输、WF 跌到 44.4%。
- 说明失败窗口是**动量因子本身**在特定时段跑输静态等权，而非"黄金占了进攻仓、错过上涨"。
- code_review_report 中"低波+黄金选股拖累"的失败窗口归因**不准确**，应修正。

### 5.3 基线 1.10 是经验最优点
- Sharpe / 年化峰值落在 1.10 附近；1.40 仅 WF 略升但 Sharpe 回落。
- 当前 `vol_w=1.10` 是经回测选择的合理值，无需调整。

## 6. 对先前 P0 建议的更正

- `output/优化改进建议.md` 中 **P0"去黄金偏好（vol_w 1.10→~0.9 或黄金改纯防御仓）"应撤回/降级为"已验证不成立"**。
