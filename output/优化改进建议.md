## 0. 总评

用价值投资的尺子量这套策略，比量单只股票更锋利。本策略本质是"动量 + 低波防御"的系统性 ETF 轮动，并非价值策略；但价值体系最硬的三把尺——**安全边际、经济护城河、能力圈**——拿来审一个量化策略，能戳中最该警惕的地方。

**核心判断**：当前最大风险不是赔钱，而是"为一段回测叙事付了过高的价"（77.8% → 55.6% 的 WF 复现事故即为典型）。策略本身的结构性护城河还不够宽。

**已确认的优势（值得保留）**：
- 工程底子扎实：配置驱动、因子集中管理（波动率 `ddof=0` 唯一源）、回测与实盘共用 `engine_core.py`、CI 含引擎↔实盘一致性校验。
- alpha 经公式修正后真实显著（DSR≈1.0，旧实现曾因钳制虚高已修正）；MC 改为仅扰动 7 个活跃参数（剔除 D4 no-op），不再宣称 100%；过拟合风险最终由 2026-07-26 真 OOS 验证（OOS 无退化）确认低。
- 138 测试全绿，文档一致性在 v3.1 已对齐（Sharpe 1.610 / 年化 17.05% / MaxDD 6.97% / 665 周）。

## P0 — 先补"安全边际"（不补则不建议上规模实盘）

### P0-1 黄金偏好是结构性软肋
- **现状**：评分 `score = mom6 − 1.10 × vol11`，`vol_w=1.10` 过度加权低波资产（黄金），平静市里黄金长期占据 TOP2。
- **证据**：WF 相对胜率 55.6%(5/9)，失败窗口为 W0/W2/W5/W7；其中 W2(2016-17)、W5(2021-22) **根本不是强牛市**——证明这是系统性缺陷而非噪声。
- **改法（二选一）**：
  1. 评分公式去黄金偏好：`vol_w` 由 1.10 降至 ~0.90，或给黄金单独降权；
  2. 将黄金从"常驻进攻仓"改为"危机相关性收敛时才显形"的纯防御仓。

### P0-2 防御信号单点依赖
- **现状**：Layer 3 防御仅依赖纳指 vol（`crisis_correlation_boost` 触发器单一）。
- **风险**：A 股独立下跌时响应滞后，错过防御切换。
- **改法**：补充 A 股本地指标——中证500 自身波动率、iVIX、或成交额萎缩率，使防御不再"看美股脸色"。

### P0-3 缺乏纯样本外验证
- **现状**：universe（沪深300 → 中证500 迁移）与参数（mom_window、vol_w 等）在同一数据集（2013-2026）上选定，存在 universe selection bias。
- **改法**：冻结 2013-2023 为训练/参数选定区间，2024-2026 作为**纯 OOS** 验证；OOS 跑赢等权基准，才算真有 edge。

## P1 — 把"护城河"讲清楚（edge 是结构性还是统计巧合？）

### P1-4 分层 Walk-Forward
- 将 55.6%(5/9) 拆成"趋势市 / 震荡市 / 危机市"各自胜率。
- 若危机市稳赢、平静市稳输 → 护城河 = 危机 alpha（珍贵但窄）；若结果随机 → 提示曲线拟合。

### P1-5 实盘成本冲击验证
- 成本敏感性表已存在（20bp 成本下 Sharpe 约 1.46），纪律良好。
- 补一层：实盘滑点 + 佣金 + **QDII 黄金/纳指的溢价与换汇成本**的实际冲击，避免报告里的 1.610 在真实成交中塌缩。

### P1-6 加一层"价值滤镜"（估值护栏）★ 价值体系专长交点
- **思路**：既然策略是动量，可在选股/配比中叠加**估值 z-score**（各 ETF 跟踪指数的 PE / PB 历史分位），作为动量信号的"估值护栏"——避免在资产极度泡沫时分位重仓。
- **定位**：不是把策略改成价值，而是给动量套上"不买贵"的缰绳，相当于给 edge 加一道安全边际。
- **可证伪性**：可直接回测——在现有 `score` 上叠加 `− λ × valuation_zscore`，扫描 λ ∈ [0, 0.5]，观察 Sharpe / MaxDD / WF 胜率的变化。
- **预期收益**：在 2015 下半、2021 初等估值极端区间降低回撤，提升下行安全边际。

## P2 — 工程卫生（工程质量要求）

### P2-7 清理死字段
- `StrategyConfig` 约 80 字段仅十几个生效，5 个实验模块（softmax / dynamic_weighting / regime_classifier 等）全 `enabled:false`。
- 建议：保留实验模块代码但精简 config schema，或移到独立 `experimental/` 命名空间，降低新人上手成本。

### P2-8 结构化日志替换 print
- 当前大量 `print` 输出，CI 与实盘难溯源。
- 建议：引入 `logging` 模块，按模块分级（INFO/WARNING/ERROR），输出到文件 + 实盘监控可消费的结构。

### P2-9 依赖版本锁定
- Kimi 审计曾发现依赖未锁版本导致的可复现性问题（含汇率对冲成本测试脚本 bug）。
- 建议：`requirements.txt` / `pyproject.toml` 锁定精确版本，CI 加依赖完整性校验。

### P2-10 调仓自动化 + 实盘监控面板
- 当前"人肉每周一手动调仓"本身有操作风险。
- 建议：脚本化 `rebalance_live.py` 定时触发 + 生成持仓/信号快照；配套 Dashboard 监控净值、偏离度、防御触发状态。

## 一句话结论
v3.1 工程底子是所有个人策略里见过的上乘，alpha 证据也真；但从价值视角看，它卖的是"低回撤 + 高夏普"的叙事，而叙事的**安全边际不足**。黄金偏好、单点防御、缺纯 OOS 三处不补，实盘等于"用 55.6% 的置信度撑 1.610 的夏普"。**先补 P0，再谈规模。**
